There is no preview pane on this page. The controls edit the actual background of the actual page, live — what you are looking at while you drag a slider is the thing you are configuring.

where the settings live

Whatever you set here is saved in localStorage under garden.bg and applies to every page on this site until you clear it. It is yours, it never leaves your machine, and it beats whatever the page itself asked for. That ordering is deliberate: a reader who has decided the background should be none should not have that overruled by an essay.

A page with no bg of its own ships four lines that look for your choice and fetch the engine only if it is there. The preference is honoured everywhere, and a reader who never set one still gets a page with no javascript on it.

five slots, and pictures

A slot is a name, a set of dials, and sometimes a picture. There are five. The dials sit in localStorage beside the live config; the pictures sit in IndexedDB, because one photograph as a data URI is most of what localStorage is allowed to hold.

Neither ever leaves your machine, and that is the point rather than a limitation. It is also the one seam in the sharing: a link can carry dials, so ?bg=plasma&bgopts=… is a background you can send to someone. A picture cannot travel, so a link to ascii with img=2 draws whatever is in your slot two — which is either a happy accident or nothing at all.

image   the picture, as a picture. a CSS layer, not a grid.
ascii   the picture, redrawn out of the charset.
mask    the picture as a stencil. text and motion, only inside it.

ascii works because a ramp ordered dark to light is a greyscale palette with about ten steps, and a photograph quantised to ten steps is still recognisably the photograph. mask is the one that looks least like its inputs: the picture does no drawing at all, it only decides where drawing is allowed, so a face and the word rot produce neither a face nor the word.

what other people left

The gallery is a list of backgrounds other people have shared, and a button that adds yours. It carries dials only — a program name, a charset, one line of k=v. The server rebuilds every submission field by field against a whitelist rather than filtering it: a filter has to imagine every attack, a whitelist only has to name the ten things that are allowed. Nothing submitted is executed, nothing submitted is a path, and no picture is accepted at all.

A hundred entries at most, newest first; past that the oldest falls off the end. Anything you post gets a delete button. When the server accepts an entry it hands your browser a token and keeps only a hash of it, so it cannot tell who you are and does not need to — the only question a delete button has to answer is whether this is the browser that posted the thing. Clear your storage and the entry stays, unowned.

The same list is on the playground, which is where you are more likely to be choosing a background in the first place. Pictures go in slots on their own page.

The query string wins so a particular field can be sent to someone: /?bg=plasma&bgopts=speed%3D2%20fade%3D.8 is a link to a specific background, not to a page that happens to have one.

putting it in a block

Three header fields, not ten — a block gets thirty-two fields in total and they are shared with title, date, tags and everything else, so the dials go on one line the way css holds one line of CSS.

bg      drift

The button above copies the current settings in that form. bg  none in a header switches the field off for one page while leaving your own preference alone everywhere else.

the dials

keywhat
fps frame cap. the field is a background; 12 is usually plenty
speed multiplies time. 0 freezes it into a texture
scale multiplies the program's own idea of size
size cell size in px. smaller is more cells and more work
fade opacity of the field. contrast against the prose
seed names the random field. same seed, same noise, every reload
word what warp dissolves. three letters works best
drift which links float: nav, body, all, none
driftspeed how fast they float. 0 pins them
rd which corner of the feed/kill plane rd runs in

Cell size is the one that costs. Ten pixels on a large display is roughly twenty thousand cells; six pixels is fifty thousand, and the arithmetic per cell has not changed but there are two and a half times as many of them.

the two layers

The field and the floating links are separate <pre> elements, and that is not tidiness. A grid with no styles and no links on it is written to the DOM as one string and one textContent assignment for the entire screen. Put a single coloured link in it and every row has to be built out of <span>s instead. Keeping the links on their own layer — where nearly every row is empty, unchanged, and skipped — is what lets the field stay on the fast path.

Nothing runs off-screen, nothing runs in a hidden tab, and under prefers-reduced-motion the field is drawn exactly once and then left alone. See the writeup and the playground.

the picture dials

keywhat
img which slot's picture, 1 to 5
fit cover, contain or tile. only image reads it
gain contrast around the midpoint, for ascii. flat photographs need it
maskthr how bright a cell must be before mask draws in it
masktext the word poured into the stencil. one token — bgopts is space separated. blank for a moving field
maskspeed how fast the text crawls through it. 0 holds it still
maskinv stencil the dark parts instead of the light
masksoft let the picture's brightness fade the field, not just clip it
